# Security policy

HealthAlyst Africa builds software that health organisations use to run
their services, so we take reports about its security seriously and thank
everyone who reports responsibly.

## Reporting a vulnerability

Report vulnerabilities privately through GitHub: open the affected
repository's **Security** tab and choose **Report a vulnerability**. Only the
repository's maintainers can see the report.

Please do not open a public issue, pull request or discussion about a
vulnerability, and do not include real personal or health data in a report.
Describe the data involved by type instead.

Include, where you can:

- the affected repository, application and address;
- steps to reproduce, or a proof of concept that uses only your own test
  accounts;
- what an attacker could do, and what data it would expose.

## What to expect

| Step                             | Target                                                    |
| -------------------------------- | --------------------------------------------------------- |
| Acknowledge the report           | Within 3 working days                                     |
| First assessment and severity    | Within 14 days                                            |
| Fix for a critical vulnerability | Within 7 days of confirming                               |
| Fix for a high vulnerability     | Within 30 days                                            |
| Fix for a medium vulnerability   | Within 60 days                                            |
| Fix for a low vulnerability      | Within 90 days, or a recorded decision to accept the risk |

We will keep you informed, agree a disclosure date with you, and credit you in
the advisory unless you ask us not to.

## Supported versions

Our applications are continuously deployed. Only the version currently in
production, built from each repository's `main` branch, receives security
fixes.

## Safe harbour

We will not pursue action against research that:

- follows this policy;
- avoids privacy violations, data destruction and service disruption;
- uses only accounts the researcher owns or has permission to use;
- stops and reports as soon as it reaches someone else's data.
